## 1. 产品定义

### 1.1 一句话

用户把自己拥有或已获授权的聊天记录交给 Agent，本地脚本算出**行为与语言的可核验统计**，再据此给出**五维沟通风格分档 + 带证据的结论 + 数据范围声明**。

### 1.2 目标用户与场景

- 想了解自己在某段关系里"怎么说话"的普通用户。
- 想复盘一段对话节奏（谁先开口、回复多快、谁在追问）的人。
- 不接受把聊天记录上传到任何服务器的用户。

### 1.3 非目标（v1 明确不做）

不做心理诊断、不做人格类型判定、不做择偶/招聘/信贷等评价用途、不做他人画像、不做群聊多人分析、不做趋势预测、不做云端存储、不训练模型、不生成聊天建议（v0.2 独立技能）。

### 2.1 D4 的落地含义（重要）

"支持微信/QQ"在本项目里的准确含义是：

1. 用户在微信/QQ 里**自己选中消息 → 复制 → 粘贴成 txt**，或使用其**自带的"导出消息记录"功能**得到 txt；
2. 本技能解析这些**文本**，不接触数据库、不接触账号；
3. 解析器对微信/QQ 的多种复制样式做容错，并在无法识别时输出"未识别行数 + 样例"，由 Agent 引导用户换一种复制方式；
4. 明确不支持：微信 `.db`（加密）、QQ `MsgEx.db`（加密+结构变动）、任何需要 root/越狱/注入的方案。

## 4. 三层输出架构

把所有输出按"确定性"分层，是这个设计最核心的结构决定。

| 层 | 内容 | 由谁产生 | 性质 | 允许出错 |
|---|---|---|---|---|
| **L1 事实层** | 消息数、会话数、天数、对象数、发起率、回复时延、burst、夜间占比、媒体占比、剔除段数 | 脚本 | 确定性统计 | 不允许 |
| **L2 倾向层** | 五维分档 + 波动带 + 样本充分度等级 + 覆盖度 | 脚本 | 统计推断 | 允许，但必须带区间与等级 |
| **L3 叙述层** | ≤3 条带证据结论 + ≤1 条双证据反差 + 限制声明 | 模型 | 语言组织 | 允许措辞偏差，不允许无证据 |

规则：**L3 的每一句结论必须能回指到 L1 或 L2 的某个字段或某条证据编号；指不到就删句。**

## 6. 数据契约

所有中间产物落在用户指定的工作目录 `<work>\`，均为 UTF-8、LF 换行、JSON 不用 ASCII 转义（`ensure_ascii=False`）。

### 6.1 `messages.jsonl`（解析产物）

每行一条消息：

```json
{"i":0,"session_id":"S001","sender":"张三","is_me":null,"ts":"2024-01-01T12:00:00+08:00","text":"你好","type":"text","raw_ts":"2024-01-01 12:00:00"}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| i | int | 全文件顺序号，从 0 开始 |
| session_id | str | `S001` 起，按时间连续性切分 |
| sender | str | 原始发送者标签（已去空白/去尾号） |
| is_me | bool/null | 解析时若给了 `--me` 则填充 |
| ts | str/null | ISO8601 带时区；无时间戳时为 null |
| text | str | 正文（多行已合并为 `\n`） |
| type | str | `text` / `media` / `system` |
| raw_ts | str | 原始时间串，便于排错 |

### 6.2 `parse_report.json`

```json
{"format":"wechat","input":"a.txt","encoding":"utf-8","messages":1234,"text_messages":1100,
 "sessions":42,"span_days":37,"senders":[{"label":"张三","count":700},{"label":"李四","count":534}],
 "me":null,"unparsed_lines":3,"unparsed_samples":["..."],"media_messages":90,"system_messages":44,
 "has_timestamps":true,"warnings":["未指定 --me"]}
```

### 6.3 `features.json`

```json
{"meta":{"messages":1234,"sessions":42,"span_days":37,"partners":1,"me":"张三","grade":"B"},
 "l1":{"my_messages":700,"my_share":0.567,"median_reply_s":420,"median_burst_chars":18.5,
       "night_ratio":0.09,"media_share":0.073,"dropped_sensitive":0},
 "features":{"initiation_ratio":{"value":0.64,"n":42,"unit":"ratio","pool":"ratio",
              "series":{"S001":{"num":1,"den":1},"S002":{"num":0,"den":1}}},
```

`pool` 取值：`ratio`（num/den 求和后相除）、`median`（合并 values 取中位）、`mean`（会话值等权平均）。

## 7. 流水线（9 步）

| 步 | 动作 | 输入 | 输出 | 继续条件 | 停止/降级条件 |
|---|---|---|---|---|---|
| 0 | 意图分流 | 用户请求 | 判断 | 明确是"分析我的聊天记录/风格" | 是"怎么回复"→指向 v0.2；是"分析别人"→拒绝 |
| 1 | 采集 | 粘贴文本 / 文件路径 | `<work>\input.txt` | 拿到文件或文本 | 只有截图 → 说明不可用，请发文本 |
| 2 | 解析 | input.txt | messages.jsonl + parse_report.json | 识别出 ≥2 个发送者且消息数 >0 | 无时间戳 → 走"纯文本模式"并告知行为特征缺失；解析失败 → 报未识别行样例 |
| 3 | 确认"我是谁" | parse_report | `--me` 参数 | 用户指认成功 | 一对一未指认 → 追问一次；群聊 → 拒绝（v1） |
| 4 | 预检与分级 | parse_report | grade | C 级以上 | D 级 → 只出 L1 事实，不出分 |
| 5 | 匿名化 | messages.jsonl | messages.anon.jsonl + anonymize_report.json | 替换完成 | 含高危敏感段 → 剔除并计数 |
| 6 | 特征 | messages.anon.jsonl | features.json | 有效文本 ≥20 条 | 文本不足 → 该维度缺失，不猜 |
| 7 | 计分 | features + anchors + weights | score.json | 覆盖度 ≥0.6 | 覆盖不足 → 该维 null，标"数据不足" |
| 8 | 证据 | features + score | evidence.json | 每维 ≥1 条 | 无证据 → 该维不出结论 |
| 9 | 撰写与自检 | score + evidence + report-template | `report.md` | rubric 全过 | 不过 → 重写，最多 2 轮 |

**硬约束：Agent 不读 input.txt / messages.jsonl / messages.anon.jsonl 的全文。** Agent 只读 parse_report / features / score / evidence 四个 JSON；snippet 由脚本截断并脱敏后放进 evidence.json。

## 9. 解析规则

### 9.1 编码

依次尝试：`utf-8-sig` → `utf-8` → `gb18030` → `utf-16`。成功即记录到 parse_report.encoding。全部失败 → 退出码 3，提示"请另存为 UTF-8"。

### 9.2 文本归一化

全角转半角仅用于**表头识别**（`／`→`/`，`：`→`:`，全角数字→半角），正文原样保留。

### 9.3 表头正则族（按优先级尝试，取匹配行数最多者）

```
P1 WhatsApp 方括号：  ^\[?(\d{1,4}[/.\-]\d{1,2}[/.\-]\d{1,4})[,，]?\s+(\d{1,2}:\d{2}(?::\d{2})?)\s*[\]\-–]\s*([^:：]{1,40})[:：]\s*(.*)$
P2 WhatsApp 破折号：  ^(\d{1,4}[/.\-]\d{1,2}[/.\-]\d{1,4})[,，]?\s+(\d{1,2}:\d{2}(?::\d{2})?)\s*[-–]\s*([^:：]{1,40})[:：]\s*(.*)$
P3 日期+时间+发送者：  ^(\d{4}[/.\-]\d{1,2}[/.\-]\d{1,2})\s+(\d{1,2}:\d{2}(?::\d{2})?)\s+(.{1,40}?)\s*$
P4 发送者+日期+时间：  ^(.{1,40}?)\s+(\d{4}[/.\-]\d{1,2}[/.\-]\d{1,2})\s+(\d{1,2}:\d{2}(?::\d{2})?)\s*$
P5 中文日期三行式：    ^(\d{4}年\d{1,2}月\d{1,2}日)\s*(上午|下午|晚上|凌晨|中午)?\s*(\d{1,2}:\d{2}(?::\d{2})?)\s*$   （下一行视为发送者）
P6 QQ 带尾号：        P3/P4 的发送者字段去掉 `(digits)` 或 `（digits）`
P7 冒号行：           ^([^:：\n]{1,40})[:：]\s*(.*)$
P8 纯文本：           无表头 → 单会话
```

判定：先跑 P1/P2（整行含内容），再跑 P3/P4/P5（表头独占一行、正文在后续行）。若某族命中行数 ≥ max(3, 非空行数×0.05) 且比其他族多，采用该族。

### 9.4 时间解析

- 支持 `YYYY/M/D`、`YYYY-M-D`、`YYYY.M.D`、`YYYY年M月D日`；两位年份视为 20xx。
- 支持 `H:MM`、`H:MM:SS`，可带 上午/下午/晚上/凌晨/中午（下午/晚上且 hour<12 → +12）。
- 只有时间没有日期时，继承上一条消息的日期；仍无 → null。
- 时区：`--tz`，默认 `+08:00`；JSON 自带偏移时以文件为准。
- 无时区信息时按 `--tz` 解释，并在 parse_report.warnings 记一条。

### 9.5 会话切分

按 ts 升序稳定排序（无 ts 保持原序），相邻消息间隔 > `--gap-hours`（默认 6.0）→ 新会话。会话 ID `S001`…；无 ts 时全部归入 `S001`。

### 9.6 消息类型判定

| 类型 | 判定 |
|---|---|
| media | 正文去空白后完全匹配 `^\[(图片|表情|动画表情|语音|视频|文件|位置|链接|转账|红包|语音通话|视频通话|名片|音乐|小程序)\]$` |
| system | 含 `撤回了一条消息`、`加入了群聊`、`邀请.*加入`、`以下为新消息`、`消息已发出，但被对方拒收`、`开启了朋友验证` |
| text | 其余且去空白后非空 |
| （丢弃） | 去空白后为空且无媒体标记 |

### 9.7 burst（连发段）

同一会话内，连续同一发送者的消息，相邻间隔 ≤120s 视为一个 burst。burst 的 `chars` = 各条 text 长度之和。用于所有长度类特征的归一化。

### 9.8 发送者归并

去首尾空白 → 去 `(数字)`/`（数字）` 尾号 → 去尾部冒号 → 合并连续空格。允许 `--alias "张三=我"` 手动归并；归并结果写入 warnings。

## 10. 匿名化

### 10.1 替换规则

| 目标 | 规则 | 替换为 |
|---|---|---|
| 发送者标签 | 全部 | `我` / `对方A` / `对方B`…（`is_me` 保留） |
| 手机号 | `1[3-9]\d{9}` | `[手机]` |
| 身份证 | `\d{17}[\dXx]` | `[证件]` |
| 邮箱 | 常规 | `[邮箱]` |
| URL | `https?://\S+` | `[链接]` |
| 银行卡 | 16–19 位连续数字且以 4/5/6 开头 | `[卡号]` |
| 自定义姓名 | `--name-list` 每行一个 | `[姓名]` |
| @提及 | `@\S{1,20}` | `[@某人]` |

### 10.2 敏感内容

关键词表（见 `assets` 内嵌）：自杀、自残、抑郁、确诊、病历、住院、流产、家暴、性侵、裸照、身份证、银行卡、密码、转账、借钱、欠款、未成年、14 岁、16 岁。

- 默认：保留原句但标 `sensitive=true`，且**不进入 snippet 候选**。
- `--drop-sensitive`：整条剔除，计数进 `anonymize_report.dropped`。
- 命中"自杀/自残/性侵/未成年"任一 → 报告顶部插入安全提示，并建议寻求专业帮助（文案见 privacy.md）。

### 10.3 输出

`anonymize_report.json`：各规则替换次数、剔除条数、敏感条数、是否触发安全提示。

## 11. 特征定义（14 项）

通用约定：
- 只统计 `type=="text"` 且 `is_me==true` 的消息（标注"对方"的除外）。
- 比率类一律 `命中数 / 分母`，分母为 0 → null。
- 所有特征都带 `n`（参与计算的消息数或会话数）与 `coverage`。

| # | 维度 | key | 定义 | pool | 证据等级 |
|---|---|---|---|---|---|
| 1 | 社交主动性 | `initiation_ratio` | 会话中我的首条消息早于对方首条 → 发起；分母为双方都有消息的会话数 | ratio | B |
| 2 | 社交主动性 | `reply_latency_median_s` | 对方消息 → 我下一条消息的间隔秒数（0<Δ≤12h）中位数 | median | B |
| 3 | 社交主动性 | `bursts_per_session` | 我的 burst 数 / 我有消息的会话数 | mean | B |
| 4 | 社交主动性 | `night_ratio` | 我的消息中本地时间 23:00–05:59 的占比 | ratio | C |
| 5 | 探索开放度 | `char_diversity_500` | 我的文本按会话拼接，seed=42 抽 500 字，unique/total | mean | B |
| 6 | 探索开放度 | `question_ratio` | 含 `？/?`，或以 吗/呢/吧/么 结尾，或以 为什么/怎么/是不是/能不能/要不要/有没有 开头的消息占比 | ratio | B |
| 7 | 探索开放度 | `turn_depth_mean` | 每会话"说话权切换次数+1"的均值 | mean | C |
| 8 | 回应亲和度 | `agree_ratio` | 命中附和短语表且未命中否定前缀的消息占比 | ratio | B |
| 9 | 回应亲和度 | `disagree_ratio` | 命中异议短语表的消息占比 | ratio | B |
| 10 | 回应亲和度 | `response_coverage` | 对方消息后 1 小时内我有消息的比例 | ratio | C |
| 11 | 条理规划度 | `structure_score` | 含标点或长度≥15 字的我的消息占比 | ratio | C |
| 12 | 条理规划度 | `plan_density` | 命中时间/计划词表的我的消息占比 | ratio | C |
| 13 | 情绪外显度 | `emotion_density` | 情绪词命中次数 / 我的文本总字数 ×100 | ratio | B |
| 14 | 情绪外显度 | `intensity_density` | （感叹号数 + 重复语气组数）/ 总字数 ×100 | ratio | C |

### 11.1 词表要点

- 附和（只用多字短语，避免"是/对/好"单词误命中）：好的、好呀、好啊、行、可以、嗯嗯、对对、确实、同意、明白、收到、没问题、有道理、说得对、是这样的、我理解、辛苦了。
- 异议：不对、不是这样、不同意、反对、没必要、算了、随便、无所谓、你错了、我不这么认为、但是我觉得、可是我觉得。
- 否定前缀排除：不行、不可以、不好、不对（"不对"整体算异议，不算附和）。
- 情绪：开心、高兴、难过、伤心、生气、烦、累、焦虑、紧张、害怕、委屈、失望、无语、崩溃、幸福、感动、喜欢、讨厌、期待、担心、郁闷、舒服、难受、心疼、委屈、气死、烦死。
- 计划：明天、后天、下周、周末、之后、之前、到时候、安排、计划、约、几点、截止、提醒、记得、时间、地点、一起。
- 重复语气组：`哈{3,}`、`啊{2,}`、`呀{2,}`、`哦{2,}`、`嗯{2,}`。

### 11.2 明确不做（v2 待验证）

承诺兑现比、长词比例、第一人称复数比例、冲突场景回应、深夜×情绪共现、话题引入率、emoji 使用、消息长度中位数（已移至 L1 事实）。

### 11.3 会话级充分统计量

为支持 bootstrap，每项特征按 `pool` 输出 `series`：
- ratio → `{"num":int,"den":int}`
- median → `{"values":[float,...]}`
- mean → `{"sum":float,"n":int}`

## 12. 计分

### 12.1 锚点插值

每项特征在 `anchors.v0.json` 里有一组 `[[raw, score], ...]`，raw 单调递增，score 0–100。线性插值，超出两端按端点截断。反向特征直接把 score 写成递减。

### 12.2 维度分

`dim_raw = Σ(w_i × s_i) / Σ(w_i)`，只对非 null 项求和；`coverage = Σ(w_i available) / 1.0`。coverage < 0.6 → 维度为 null。

### 12.3 权重（v0 先验）

| 维度 | 项与权重 |
|---|---|
| 社交主动性 | initiation .30 / latency .25 / bursts .25 / night .20 |
| 探索开放度 | diversity .40 / question .30 / turn_depth .30 |
| 回应亲和度 | agree .40 / disagree .30 / coverage .30 |
| 条理规划度 | structure .50 / plan .50 |
| 情绪外显度 | emotion .50 / intensity .50 |

### 12.4 bootstrap

- 单位：会话（有放回重采样）。
- B=1000，seed=42，用 `random.Random(42)`。
- 每次重采样后按 11.3 的 series 重建 pooled raw → 重算 item → 重算 dim。
- 输出 P10、P90 作为 `range`，标注"会话间波动范围"。
- 会话数 <8 → 跳过，range=null，warning。

### 12.5 敏感性

删除 30% 会话（5 个种子，seeds 1–5），重算维度分，取 `max|Δ|`。stability：≤8 high，≤15 medium，>15 low。low → 报告里该维降一档表述并标"不稳定"。

### 12.6 样本分级

| 级 | 条件 | 输出权限 |
|---|---|---|
| A | ≥1500 条 且 ≥30 天 | 全部；可对比 |
| B | ≥300 条 且 ≥10 天 | 全部；标"中置信" |
| C | ≥120 条 且 ≥5 天 | 只出 L1 + 定性描述；不出分 |
| D | 其余 | 拒绝分析 |

v1 只支持一对一，对象数恒为 1，因此不再作为分级条件（v1.0 设计里 A 级要求 ≥3 个对象，实际不可达）。
门槛按"1:1 聊天靠复制能凑到的量"重定：300 条 / 10 天是普通用户十几分钟能收集到的量级。

### 12.7 分档

0–19 低 / 20–39 偏低 / 40–59 中 / 60–79 偏高 / 80–100 高。
若 `range` 跨档 → 输出"中偏高（波动 52–71）"形式，不输出单一档位。
不输出总分、不排序、不比较维度高低。

## 13. 证据规则

1. 每维取贡献度 `w_i × |s_i − 50| / Σ` 最高的 1–2 项。
2. 每条证据必须包含：特征名、可读统计（带数字）、可选 snippet。
3. snippet：取该特征命中的第一条文本消息，截断 40 字，`sensitive=true` 的跳过；全文最多 3 条 snippet。
4. 维度无证据 → 该维在报告里写"数据不足，未评估"，不写结论。
5. 反差：仅当存在 `score≥65` 与 `score≤38` 的两维，且两者各有 ≥1 条证据时才输出；否则整节删除。

## 19. 风险与已知局限

| 风险 | 影响 | 缓解 |
|---|---|---|
| 规则加权效度仅 0.15–0.25 | 分档与真实自评相关弱 | 文案强度按此设定；只讲"这段记录的说话方式"，不讲"你是什么人" |
| 微信/QQ 复制格式随版本变化 | 解析失败 | 多族正则 + 未识别行反馈 + 引导换导出方式 |
| 中文分词缺失 | 词级特征用短语表近似 | 只用多字短语，不用单词；文档写明 |
| 单对象 → 最高 B 级 | 无法对比 | 明确写进报告 |
| 用户发来他人记录 | 伦理风险 | 第 0 步与 SKILL.md 双处拒绝 |
| 敏感内容 | 合规风险 | 匿名化前置 + 安全提示 + 删除指引 |
